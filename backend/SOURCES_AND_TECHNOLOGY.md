# 🧰 VoiceShield AI — Technology & Data-Source Document (SIH-Grade)

> This document is the single source of truth for:
> 1. Every technology the project **uses**
> 2. Every technology the project **could** use (roadmap)
> 3. Every **data source** used for training/evaluation — with links, license, why it's used, and how it complies with Smart India Hackathon (SIH) rules

**SIH compliance principle (checked):**
- All data comes from **redistributable open licenses** (CC-BY-4.0, CC0, MIT, Apache-2.0) or is **self-generated on-site** (TTS spoofs AND real voice-clone impersonation via XTTS-v2 / RVC / FreeVC).
- No proprietary, paywalled, personal, or NDA-bound data is used.
- Model weights used are open-license or our own fine-tunes of open-license weights.
- Findings PDFs / PDFs / logs are generated by us — no copyrighted content embedded.

**Cloud training pipeline (Colab/Kaggle):** see `cloud/…` at the repo root —
`cloud_dataset.py` (this file's sibling) builds a *large* SIH-safe corpus with
REAL A.I. voice impersonation; `cloud/build_notebooks.py` generates Colab &
Kaggle notebooks that execute it on free GPU. Everything below documents both
the on-device and the cloud pipeline.

## 4. Which data is used and WHY (summary table)

| Need | Data used | Why this data |
|---|---|---|
| Learn "what a real Indian voice sounds like" | FLEURS hi/en/kn/ta/te/ml/mr bonafide + Common Voice (CC-BY-4.0) top-up | Real humans, 7+ Indian languages, CC-BY-4.0 (Common Voice 14+; CC0 ≤ 13) |

| Learn the broader voice-conversion attack family | RVC / FreeVC conversion spoofs (any language) | Second major real-world deepfake technique |
| Learn "what a plain TTS robocall sounds like" (minority class) | edge-tts / gTTS spoofs | Simpler attack the model must also catch, but not the primary focus |
| Simulate degraded phone channels | G.711/AMR/packet-loss/bandwidth/noise augmentations | Indian mobile calls are codec-degraded; model must see that in training |

| Fallback / custom path | local AASIST-L fine-tune | Fully ours, MIT, retrainable with the pipeline |
| Realistic adversarial check | FreeVC24 clips (local eval) | Voice-cloning (the actual SIH problem) rather than plain TTS |

SIH requires: **(a)** original work, **(b)** no violation of third-party IP, **(c)** open/citable datasets, **(d)** no plagiarised content.

| SIH requirement | How VoiceShield satisfies it |
|---|---|
| Open / citable datasets | FLEURS is CC-BY-4.0 with a DOI/citation; we document every source + link in this file |

| No scraping personal data | FLEURS is a public read-aloud corpus; no telephony/PII scraped |
| Redistribution / license compliance | CC-BY-4.0 requires attribution → given in Sections 3 & 6; MIT/Apache-2.0 → NOTICE retained |

| Human rights / ethics | Child Shield & DPDP-limited processing align with responsible-AI norms |
| Suspected vs confirmed fraud flows | **Suspected** (pre-fraud): optional `CHAKSHU_DIP_WEBHOOK_URL` routes flagged-call metadata toward DoT Sanchar Saathi / Chakshu / DIP for network-level action. **Confirmed** (post-fraud, victim): forensic PDF directs to 1930 / cybercrime.gov.in / RBI Sachet (`https://sachet.rbi.org.in`). ## 7. Data-flow diagram (what leaves the machine)

```
Mic / call audio  ──►  WebSocket  ──►  Ring buffer (RAM)  ──►  features + model
                                                                  │
                                                                  ▼
                                              scalar scores only  ──►  dashboard / alerts
                                                                  │
                                                                  ▼
                                incident telemetry (non-PII scalars) ──► store / PDF / ledger
```

- Raw audio is **never persisted** by the live path.
- Only scalar sub-scores (synthetic_score, jitter, shimmer, phase, verdict) are stored/displayed.

## 8. DPDP Act 2023 — data-protection posture

Mapping of Digital Personal Data Protection Act (§) obligations to the design:

| DPDP principle | How VoiceShield complies |
|---|---|
| **Lawful purpose** (§4: notice + purpose) | Processing is confined to fraud-detection notice shown in the UI; no secondary use of audio |
| **Data minimization** (§4, §8) | Only scalar model scores (synthetic_score, jitter, shimmer, phase, verdict) are kept; raw audio lives in RAM and is overwritten every window, never persisted by the live path |
| **Purpose limitation** | Audio is processed for the single purpose of voice-integrity verdicts; embeddings are one-way (engine/speaker.py) making speech unreconstructable |
| **Storage limitation** (§8) | Logs/telemetry store non-PII scalars only; forensic PDFs are encrypted (AES-256-GCM) under org-custody keys; ledger stores hashes + CID + key fingerprint, never content |
| **Security safeguards** (§8) | HTTPS for API/WS in deployment, app-password SMTP, encrypted reports, IPFS ciphertext pinning, PoW tamper-evidence |
| **Data-principal rights** (§11–§13) | Delegated to the operator via `backend/app/compliance/dpdp.py` helpers; Child Shield requires explicit guardian consent in the UI copy |
| **Breach notification** (§8(6)) | `backend/app/compliance/dpdp.py` exposes notification helpers for reported incidents (alert + audit trail) |

## 9. Zero-cost / resource posture

- All alert channels (Telegram, Gmail app-password SMTP, ntfy.sh, Fast2SMS,
  webhook) are free or free-tier; every channel is optional (missing keys are
  skipped at runtime).
- Optional persistence uses Neon's free serverless postgres (blank
  `DATABASE_URL` = in-memory store, fully functional).
- The NBF anchor network runs entirely on free resources: Oracle Cloud
  **Always Free** Ampere ARM VM (4 OCPU/24 GB cap) or WSL2 Ubuntu on a laptop —
  `deploy/nbf-fabric/`. No paid domains, load balancers, or API keys.
- Training runs on free GPUs (Google Colab free T4 / Kaggle GPU) with
  open-license data only.
